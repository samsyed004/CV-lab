# Lab 02 — Effect of Image Filtering on Skin-Lesion Classification

## Overview

This experiment investigates how five spatial-domain image filters affect the performance of the three best pretrained models identified in Lab Activity 1, when classifying skin lesions from the HAM10000 dataset.

**Dataset:** HAM10000 (Human Against Machine with 10000 training images)
Source: https://www.kaggle.com/datasets/kmader/skin-cancer-mnist-ham10000
7 diagnostic classes: akiec, bcc, bkl, df, mel, nv, vasc (or an instructor-approved subset — see Configuration below).

**Models evaluated:** the top three models by accuracy from Lab Activity 1's Table 1 (auto-loaded from `table1_models.csv` if available, otherwise set manually in the notebook).

**Filters evaluated:** No Filter (baseline), Average, Gaussian, Median, Sharpening, Sobel edge.

This gives 3 models × 6 conditions = 18 total training runs, all using the same dataset split, preprocessing pipeline, and training hyperparameters for a fair comparison.

## How to Run

1. Open `lab02_filter_effect_analysis.ipynb` in Google Colab.
2. Set the runtime to GPU (Runtime → Change runtime type → GPU).
3. One-time Kaggle setup, if not already done for this Colab account:
   - Get an API key from kaggle.com/settings → API → "Create New Token."
   - In Colab, open Secrets (🔑 icon in the left sidebar) and add `KAGGLE_USERNAME` and `KAGGLE_KEY`, then enable notebook access for both.
4. (Optional) If you have `table1_models.csv` from Lab Activity 1, upload it into the Colab session before running — the notebook will automatically select the top 3 models from it. Otherwise, edit `BEST_MODELS` directly in the Configuration cell.
5. (Optional) Set `CLASS_SUBSET` and/or `SAMPLES_PER_CLASS` in the dataset preparation section to run on a smaller subset of HAM10000 for faster iteration.
6. Run all cells in order (Runtime → Run all).
7. On completion, `lab02_results.xlsx` downloads automatically with all result tables.

## Notebook Structure

The notebook is organized into the following sections, matching the task requirements:

1. **Dataset preparation** — downloads HAM10000, builds a class-stratified train/val/test split (fixed across all experiments)
2. **Model loading** — loads each pretrained architecture with a classification head sized to the number of classes in use
3. **Baseline experiment** — the "No Filter" condition, using unfiltered images
4. **Image filtering** — implementations of the Average, Gaussian, Median, Sharpening, and Sobel filters, applied on the fly in the data pipeline
5. **Training** — fine-tunes each model under each filter condition with identical hyperparameters
6. **Evaluation** — computes Accuracy, Precision, Recall, F1-score, Macro-F1, AUC, balanced accuracy, confusion matrices, and per-class metrics
7. **Visualization** — class distribution, filtered image examples, training/validation curves, confusion matrix heatmaps, ROC curves
8. **Comparative analysis** — quantifies each filter's effect relative to baseline, per model, and checks whether that effect is consistent across models

## Notes on Configuration

- `EPOCHS`, `BATCH_SIZE`, `LR`, and `IMG_SIZE` are set once in the Configuration section and reused for every run.
- A fixed random seed (`SEED = 42`) is used for the dataset split and model initialization so results are reproducible.
- If running on the full HAM10000 dataset feels too slow on a free-tier Colab GPU, use `SAMPLES_PER_CLASS` to cap the dataset size for a first pass, then increase it for final results.
